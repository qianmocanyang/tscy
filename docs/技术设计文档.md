# 游戏实时同声传译系统（tscy）· 技术设计文档

> 版本：v1.0　|　平台：Windows（主）/ Linux·macOS（副）　|　运行时：Python 3.13

---

## 0. 一句话概要

常驻后台的 Python 进程：你说话 → 程序自动判断你说的是中/英/韩/日/俄哪一种 → 翻译成你指定的目标语言 → 以**游戏内置字幕**（置顶透明窗口）+ **语音播报**两种方式返回，全程由**可自定义按键**驱动，不占用鼠标、不打断游戏操作。

## 1. 需求拆解与交互定义

### 1.1 原始需求 → 功能点映射

| 原始描述 | 拆解后的功能点 | 实现模块 |
|---|---|---|
| 开启功能后自动识别中英韩日俄 | ① 语种自动检测（LID），不依赖用户手动指定源语言<br>② 五种语言的高精度语音识别（ASR） | `asr/whisper_engine.py` |
| 说话后识别到语言 | ③ 端点检测（VAD）：自动判断"什么时候开始说、什么时候说完了"<br>④ 麦克风实时采集 | `audio/capture.py`<br>`audio/vad.py` |
| 返回中文或者其他语言（可选定） | ⑤ 目标语言可配置 + 运行中热切换<br>⑥ 多后端翻译，支持中英韩日俄两两互译 | `config.py`<br>`translate/*` |
| 按定制键位返回设定好的语言 | ⑦ 全局热键（游戏全屏状态下也能响应）<br>⑧ 三种触发模式适配不同游戏节奏 | `hotkey.py`<br>`pipeline.py` |
| 游戏场景 | ⑨ 置顶、透明、**鼠标点击穿透**的字幕浮层<br>⑩ 低延迟、低 CPU 占用、不影响游戏帧率 | `output/overlay.py`<br>`output/tts.py` |

### 1.2 三种触发模式（核心设计决策）

游戏里**不能**让麦克风 7×24 小时持续识别——环境噪声、游戏音效、队友语音都会被误识别，而且持续推理会抢 CPU 影响帧率。所以本程序提供三种模式，通过配置切换：

| 模式 | 配置值 | 操作方式 | 适用场景 | 延迟 |
|---|---|---|---|---|
| **A. PTT 按住说话** | `ptt` | **按住**热键说话 → **松开**即自动识别+翻译+输出 | 竞技类游戏、需要即时反馈 | 最低，松手即出 |
| **B. 两步式**（默认） | `two_step` | 按【录音键】开始 → 再按【录音键】停止 → 按【翻译输出键】才翻译并输出 | 原始需求描述的流程；适合想先确认识别原文再翻的场景 | 可控，人工决定时机 |
| **C. 自动监听** | `auto` | 无需按键，VAD 检测到说话自动收音，静音超时自动提交 | 挂机聊天、看外语直播/视频 | 全自动，但受噪声影响 |

**为什么把"识别"和"翻译输出"拆成两个独立动作？**
这是对你原始需求（"识别到语言后，按键返回设定语言"）的直接落地。拆解带来两个额外好处：

1. **可纠正**：两步模式下，识别完会先把**原文**显示在浮层上，你确认没听错再按输出键去翻译，避免"听错一句 → 翻错一句 → 队友误解"的连锁错误。
2. **省 API**：识别是本地免费的，翻译要走网络。两步模式让你能丢弃无效片段，不浪费翻译额度。

### 1.3 交互时序（模式 B 两步式）

```
用户              热键层           采集/VAD         ASR(Whisper)      翻译层        输出层
 │                 │                  │                  │              │            │
 ├─ 按 F9 ────────▶│                  │                  │              │            │
 │                 ├─ start ─────────▶│ 开始收音          │              │            │
 │  🎤 说话中...    │                  │ 实时 VAD 检测     │              │            │
 │                 │                  │                  │              │            │
 ├─ 按 F9 ────────▶│                  │                  │              │            │
 │                 ├─ stop ──────────▶│ 提交音频片段       │              │            │
 │                 │                  ├─────────────────▶│ 转录+语种检测  │            │
 │                 │                  │                  ├─ 原文+语种 ──▶│            │
 │                 │                  │                  │              │  显示原文   │
 │                 │                  │                  │       (浮层: "Привет [ru]")│
 │                 │                  │                  │              │            │
 ├─ 按 F10 ───────▶│                  │                  │              │            │
 │                 ├─ emit ───────────────────────────────────────────▶ │ 翻译        │
 │                 │                  │                  │              ├─ 译文 ────▶│
 │                 │                  │                  │              │  字幕 + 语音│
```

## 2. 技术选型

### 2.1 语音识别（ASR）选型

| 方案 | 多语言 | 离线 | 延迟(CPU) | 内存 | 结论 |
|---|---|---|---|---|---|
| **faster-whisper (CTranslate2)** | ✅ 99 种，含中英韩日俄，且**自带语种检测** | ✅ | base 模型 2s 音频 ≈ 0.4~0.8s | ~500MB | ✅ **选定** |
| openai-whisper (PyTorch) | ✅ | ✅ | 慢 3~5 倍 | ~2GB | ❌ 太重 |
| Vosk | ✅ 但需为每种语言单独下模型 | ✅ | 快 | ~50MB/语言 | ❌ 无统一语种检测 |
| SpeechRecognition + Google API | ✅ | ❌ | 网络往返 1~2s | 极小 | ❌ 需联网、延迟不可控 |
| Azure / OpenAI Whisper API | ✅ | ❌ | 1~2s | 极小 | ⚠️ 作为可选后端预留 |

**选 faster-whisper 的三个决定性理由：**

1. **语种检测是免费的副产品**。Whisper 的 `detect_language()` 直接返回 `(语言代码, 置信度)`，不需要额外的语言识别模型——这正是"自动识别中英韩日俄"最省事的实现。
2. **不需要 PyTorch**。它跑在 CTranslate2 上，依赖体积只有 PyTorch 方案的 1/4，装包不容易翻车。
3. **内置 VAD**。解码时可开启 `vad_filter`，能滤掉游戏音效带来的静音段误识别。

### 2.2 翻译选型

| 后端 | 配置值 | 需 Key | 质量 | 额度 | 国内实测 |
|---|---|---|---|---|---|
| **自动探测** | `auto` | — | — | — | ✅ **默认值**，见 2.2.1 |
| Google（非官方端点） | `google` | ❌ | 中上 | 无限额（会被限流） | ❌ 连接超时 |
| MyMemory | `mymemory` | ❌（填邮箱提额） | 中 | 匿名 5000 字/日 | ✅ 可用 |
| DeepL | `deepl` | ✅ | **最高** | 免费 50 万字/月 | ✅ 端点可达 |
| OpenAI 兼容 API | `openai` | ✅ | 高（且能做游戏术语上下文） | 按量付费 | ⚠️ 取决于填的 base_url |
| 不翻译 | `none` | ❌ | — | — | — |

采用**策略模式 + 责任链降级**：主后端失败（超时/限流/Key 失效）自动切到 `fallback` 后端，都失败则保留原文并标红提示。

#### 2.2.1 为什么默认是 `auto` 而不是写死一个后端

在成都的家用宽带环境下对各免费端点做了实测，结果差异极大：

| 端点 | 实测结果 |
|---|---|
| `translate.googleapis.com` / `translate.google.com` | ❌ ConnectTimeout（约 6s 超时） |
| `fanyi.youdao.com`（有道） | ❌ ReadTimeout |
| `api-edge.cognitive.microsofttranslator.com`（微软/Bing） | ❌ ReadTimeout |
| `libretranslate.com` | ❌ HTTP 403 |
| `api.mymemory.translated.net` | ✅ 200，正常返回译文 |
| `api-free.deepl.com` | ✅ 可达（403 是因为没带 Key，配 Key 后可用） |

**结论**：没有任何一个免费后端能保证在全球所有网络下可用。写死默认值会变成"开发者机器上能用、用户机器上一直报错"。

所以 `backend` 默认设为 `auto` —— 程序启动时按 `deepl → openai → mymemory → google` 顺序，对每个**已配置且可用**的后端试译一句 `hello`，选出第一个真正连通的，之后一直用它。整个过程只在首次翻译时发生一次，耗时不到 1 秒。

> 想要最稳定的质量：去 DeepL 申请一个免费 Key（50 万字/月），写进 `config/secrets.json`。
> `auto` 会优先探测到它并使用，同时保留 MyMemory 作为断网降级。

> **关键优化**：当目标语言设为 **English** 时，直接用 Whisper 的 `task="translate"` 模式一步输出英文译文，**跳过整个翻译层**——省掉一次网络往返（约 0.3~0.5s），且质量不错。

### 2.3 语音播报（TTS）

| 方案 | 离线 | 音质 | 多语言 | 说明 |
|---|---|---|---|---|
| **edge-tts** | ❌ | **接近真人** | ✅ 中英韩日俄全支持 | ✅ 默认。调用微软 Edge 的在线合成接口，免费 |
| pyttsx3 (SAPI5) | ✅ | 机械 | 取决于系统装了哪些语音包 | 离线兜底 |

### 2.4 其余组件

| 组件 | 选型 | 理由 |
|---|---|---|
| 音频采集 | `sounddevice` | PortAudio 封装，回调式低延迟，跨平台，有预编译 wheel |
| 端点检测 | 自研能量 VAD（纯 numpy） | `webrtcvad` 在 Python 3.13 上需编译易失败；能量 VAD 零依赖、参数直观可调 |
| 全局热键 | `keyboard` | 支持组合键、支持"按下/松开"分别回调（PTT 必需）。⚠️ Windows 下需**管理员权限** |
| 字幕浮层 | `tkinter` + `ctypes` | 标准库零安装；用 Win32 API 设置 `WS_EX_LAYERED + WS_EX_TRANSPARENT` 实现**真透明 + 鼠标穿透** |
| 系统托盘 | `pystray` | 托盘图标与快速菜单，复用 app logo |
| 设置面板 | `tkinter` Canvas 自绘 | 不用默认 widget，暗色玻璃拟态 + 蓝紫渐变 |
| 打包 | `PyInstaller` + `Inno Setup` | 单 exe 与安装包两种形态 |

> ⚠️ **Python 解释器必须自带 tkinter**。本项目实测：WorkBuddy 托管的 Python 3.13.12
> （python-build-standalone 构建）**不含 tkinter**，浮层会直接启动失败；
> 系统安装的 python.org 官方版 3.14.4 带 tkinter 8.6，可正常运行。
> `install.bat` 会自动探测并优先选择带 tkinter 的解释器建虚拟环境。
> 自检命令 `python main.py --selftest` 会明确报告 tkinter 是否可用。
| 配置 | JSON + 文件监听热重载 | 改配置不用重启程序 |
| 缓存 | LRU 内存 + 磁盘持久化 | 游戏里重复话术（"got it""nice""谢谢"）极多，命中缓存 = 零延迟 |

## 3. 系统架构

### 3.1 分层架构

```
┌─────────────────────────────────────────────────────────────┐
│  用户交互层   keyboard 全局热键  /  CLI 命令行               │
├─────────────────────────────────────────────────────────────┤
│  编排层       pipeline.py  —— 状态机 + 队列 + 线程调度        │
├──────────┬──────────┬──────────┬──────────┬─────────────────┤
│ 采集层    │ 识别层    │ 翻译层    │ 输出层    │ 配置/日志       │
│ capture  │ whisper  │ translate│ overlay  │ config          │
│ vad      │ engine   │ +cache   │ tts      │ logger          │
└──────────┴──────────┴──────────┴──────────┴─────────────────┘
```

### 3.2 数据流

```
麦克风 16kHz 单声道
    │  sounddevice 回调（每 30ms 一帧）
    ▼
[环形缓冲] ──▶ VAD 状态机 ──▶ 判定"说完" ──▶ 截取音频段 (float32 ndarray)
                                                    │
                                                    ▼
                                    ┌───────────────────────────┐
                                    │  Whisper 引擎              │
                                    │  ① detect_language → 语种  │
                                    │  ② transcribe  → 原文      │
                                    └───────────┬───────────────┘
                                                │  Utterance(text, lang, conf)
                                                ▼
                        ┌────────── 模式判定 ──────────┐
                        │                              │
                  PTT/auto 模式                   two_step 模式
                   直接继续                    先显示原文，等待输出键
                        │                              │
                        └──────────┬───────────────────┘
                                   ▼
                    目标语言 == 源语言 ?  ── 是 ──▶ 直接输出（跳过翻译）
                                   │ 否
                                   ▼
                    目标语言 == English ? ── 是 ──▶ Whisper task=translate
                                   │ 否
                                   ▼
                        ┌──────────────────┐
                        │ 翻译层            │
                        │ LRU缓存 → 主后端  │
                        │   ↓失败           │
                        │ 降级后端 / none   │
                        └────────┬─────────┘
                                 ▼
                    ┌────────────┴────────────┐
                    ▼                         ▼
            字幕浮层 overlay            TTS 语音播报
            (置顶/透明/穿透)            (edge-tts / pyttsx3)
```

### 3.3 线程模型（4 个线程，各司其职）

| 线程 | 职责 | 为什么独立 |
|---|---|---|
| **Main** | 运行 tkinter 主循环（浮层 UI） | tkinter 必须在主线程；同时响应退出信号 |
| **Audio Callback** | PortAudio 后台线程，收 PCM 帧入缓冲 | 实时性要求最高，绝不能被推理阻塞 |
| **Worker** | 消费音频段：ASR → 翻译 | 重计算/网络 IO 放这里，卡住也不影响收音 |
| **Hotkey** | `keyboard` 监听线程 | 第三方库内部线程，回调里只发信号不干重活 |

线程间通过 `queue.Queue` 传递，避免共享状态加锁。**铁律：热键回调里只做"发信号"，绝不做推理**（否则按住键时整个热键系统会卡死）。

### 3.4 核心数据结构

```python
@dataclass
class Utterance:
    text: str            # 识别出的原文
    lang: str            # 检测到的源语言代码 (ISO 639-1: zh/en/ko/ja/ru)
    lang_conf: float     # 语种置信度 0~1
    asr_ms: int          # 识别耗时(毫秒)
    at: float            # 时间戳

@dataclass
class Translation:
    src: Utterance
    text: str            # 译文
    target: str          # 目标语言代码
    backend: str         # 实际使用的翻译后端名
    cached: bool         # 是否命中缓存
    ms: int              # 翻译耗时
```

## 4. 模块详细设计

### 4.1 `audio/capture.py` — 麦克风采集

| 项 | 值 |
|---|---|
| 输入 | 设备 ID（`None` = 系统默认） |
| 输出 | `float32` ndarray，16kHz 单声道（Whisper 的硬性要求） |
| 关键参数 | `sample_rate=16000`、`blocksize=480`（30ms）、`channels=1` |

设计要点：
- 用 `sounddevice.InputStream` 的**回调模式**（非阻塞读），回调里只做一次 `queue.put` + 环写入，不做任何重活。
- 自动重采样：若声卡不支持 16k，在回调里做简单线性重采样兜底。
- 提供 `list_devices()` 静态工具，供 `--list-devices` 命令行输出。

### 4.2 `audio/vad.py` — 端点检测

纯 numpy 实现的能量 VAD，状态机两态：`SILENCE` ⇄ `SPEAKING`。

| 参数 | 默认 | 含义 | 调参建议 |
|---|---|---|---|
| `frame_ms` | 30 | 分帧长度 | 保持默认 |
| `start_db` | -40 | 起说阈值（dBFS） | 麦克风灵敏/环境吵 → 调高到 -35 |
| `end_db` | -45 | 落音阈值（dBFS） | 比起说低 5dB，形成**滞回**，防抖 |
| `start_frames` | 3 | 连续 N 帧超阈值才算"开始说" | 防爆音误触发 |
| `silence_ms` | 600 | 静音持续多久判定"说完" | 说话慢 → 调大到 900 |
| `max_ms` | 15000 | 单次最长录音，防忘松手 | — |
| `min_ms` | 300 | 短于此长度直接丢弃 | 防喷麦/噪声 |

> **滞回（hysteresis）设计**：起说阈值 -40dB、落音阈值 -45dB，两者留 5dB 余量。这样在临界音量附近不会疯狂翻转状态——这是所有 VAD 都必须处理的经典问题。

### 4.3 `asr/whisper_engine.py` — 识别与语种检测

| 参数 | 默认 | 说明 |
|---|---|---|
| `model_size` | `base` | `tiny`(最快/最糙) `base` `small` `medium` `large-v3`(最准/最慢) |
| `device` | `auto` | 自动检测 CUDA，有显卡走 GPU，否则 CPU |
| `compute_type` | `auto` | GPU→`float16`，CPU→`int8`（量化提速 2~3 倍，精度损失极小） |
| `beam_size` | `1` | 贪心解码。**实时场景不要开 beam search**，5→1 能省 60% 时间 |
| `vad_filter` | `true` | 二次过滤静音段 |
| `condition_on_previous_text` | `false` | 关闭跨句上下文，防止上一句的语种"污染"下一句 |

语种检测：`detect_language(audio)` 取音频前 30s（不足则全取）→ 返回 `(lang_code, probability)`。
**置信度过低（< `min_conf`，默认 0.5）时**在浮层上打低置信标记，提示可能听错。

模型缓存：模型文件下载到 `models/`，首次运行自动拉取，之后复用。

### 4.4 `translate/` — 翻译层

```
       ┌─────────────┐
       │ Translator  │  ← 统一门面，负责：缓存查询 → 主后端 → 降级后端
       └──────┬──────┘
   ┌──────────┼──────────┬──────────┬──────────┐
┌──▼──┐  ┌───▼───┐  ┌───▼───┐  ┌──▼───┐  ┌──▼──┐
│Google│  │MyMemory│ │ DeepL │  │OpenAI│  │None │
└──────┘  └────────┘ └───────┘  └──────┘  └─────┘
                  ↑ 全部实现 BaseTranslator.translate(text, src, tgt) -> str
```

| 机制 | 说明 |
|---|---|
| **语言代码适配** | 各后端代码格式不同（Google `zh-CN` / DeepL `ZH` / MyMemory `zh-CN`），统一由 `LANGS` 注册表转换 |
| **缓存** | Key = `md5(src_lang|tgt_lang|text)`，LRU 上限 2000 条 + 落盘 `cache/trans.json` |
| **超时与重试** | 单后端超时 `timeout`（默认 6s），失败重试 1 次后切降级后端 |
| **长文本切分** | Google 端点对超长 query 会截断，按 500 字切块后拼接 |
| **术语表** | OpenAI 后端可注入 `glossary`（如 "gg=打得漂亮"），让翻译懂游戏黑话 |

### 4.5 `output/overlay.py` — 游戏字幕浮层

| 特性 | 实现方式 |
|---|---|
| 窗口置顶 | `attributes('-topmost', True)` |
| 背景透明 | `attributes('-transparentcolor', '#010203')` 指定某种颜色完全透明 |
| **鼠标穿透** | `ctypes` 调 `SetWindowLong` 加 `WS_EX_TRANSPARENT \| WS_EX_LAYERED`——**不会挡住游戏里的任何点击** |
| 无边框无标题栏 | `overrideredirect(True)` |
| 圆角/半透明底 | tkinter 无原生圆角 → 在 Canvas 上用**多边形逼近**画圆角矩形，配半透明填充色 |
| 双语显示 | 上行小字原文（带语种标签） + 下行大字译文，可配置显示哪几行 |
| 自动消失 | 每条字幕显示 `duration_ms`（默认 5000）后淡出 |

> 为什么不用 PyQt？PyQt5/PySide6 体积大、Python 3.13 的 wheel 不稳定。tkinter 是标准库，配合 Win32 API 完全能做到同样的视觉效果，且零安装风险。

### 4.6 `output/tts.py` — 语音播报

- **主路 `edge-tts`**：异步合成 MP3 到内存 → `pygame`/系统播放器播放。为避免重复下载同一句话，做**文件级缓存**（Key = `md5(lang|voice|text)`，存 `cache/tts/*.mp3`）。
- **兜底 `pyttsx3`**：离线，但音色机械、且依赖 Windows 已安装对应语言的语音包。
- **并发控制**：播报队列串行播放，新句子到达时可配置 `interrupt=true` 打断上一条（避免语音排队越积越久）。

## 7. 延迟预算与性能优化

以默认 `base / int8 / CPU（Ryzen 5 5600H）` 估算：

| 阶段 | 耗时 | 说明 |
|---|---|---|
| 尾音等待 | ~600ms | `vad.silence_ms` |
| Whisper 转录 | 400~800ms | 2 秒音频；换 `tiny` 可压到 ~250ms，换 `small` 约 1.2~1.8s |
| 语种检测 | ~50ms | 与转录共享特征，开销极小 |
| 翻译 | 200~500ms | 网络往返；**命中缓存 = 0ms** |
| TTS 合成 | 400~800ms | `edge-tts`；**命中缓存 = ~50ms**（直接播本地文件） |
| **端到端（缓存未命中）** | **1.6~2.7s** | 从"说完"到"听到译文" |
| **端到端（全部命中缓存）** | **~0.8s** | 重复话术的实际情况 |

**优化手段清单：**

1. `beam_size=1` 贪心解码 —— 实时场景性价比最高的一项
2. `int8` 量化 —— CPU 上提速 2~3 倍
3. 两级缓存（翻译 LRU + TTS 文件缓存）—— 游戏话术高度重复，实测命中率可达 30%+
4. 目标语言 = English 时走 Whisper `task=translate`，跳过翻译层
5. 源语言 = 目标语言时直接输出，跳过翻译层
6. 模型常驻内存，不重复加载
7. 有 N 卡时 `device=cuda` + `float16`，转录可压到 100ms 内

## 10. 风险与已知限制

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 全局热键需管理员权限 | 非管理员下按键无响应 | `run.bat` 内置 UAC 提权；启动失败时明确报错提示 |
| Google 非官方端点可能被限流 | 翻译失败 | 自动降级到 MyMemory；生产建议配 DeepL/OpenAI Key |
| 游戏音效干扰 VAD | 误触发录音 | 提高 `vad.start_db`；或用 PTT 模式（最稳） |
| Whisper 对游戏术语识别差 | 人名/技能名听错 | OpenAI 后端支持术语表注入 |
| 首次运行需下载模型 | base 约 150MB | 提示下载进度；模型缓存复用 |
| 全屏独占模式下浮层可能被遮挡 | 看不到字幕 | 建议游戏用"无边框窗口"模式（绝大多数游戏支持） |
| CPU 占用 | 低配机可能掉帧 | 换 `tiny` 模型；或关 TTS 只留字幕 |

## 附录 A：为什么"自动语种检测"在技术上更容易被忽略

很多同传工具要求用户手动选源语言，是因为它们的 ASR 引擎是**单语模型**——一个模型只认一种语言，必须先选对模型才能识别。

Whisper 是**多语统一模型**：中英韩日俄在同一套权重里，靠 `detect_language()` 在解码前对音频做一次语言分类。所以"自动识别五种语言"这个需求，用 Whisper 几乎是零成本实现的——不需要五个模型、不需要先跑一遍分类再切换，一次前向传播同时给出**语种**和**文本**。

这也是本方案把 ASR 唯一选定为 Whisper 系的根本原因。
